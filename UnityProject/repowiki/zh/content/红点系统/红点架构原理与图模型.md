## 简介
本文解释红点系统运行时的数据结构与算法：图怎么存、脏怎么传、态怎么聚合。使用层视角见 [红点使用指南](红点使用指南.md)。

## 图模型：DAG + 邻接表
- `DAG.cs`：有向无环图约束层——加边走 `Insert`，构成环即失败（配置级错误硬报错，运行时挂父同样走环检测）
- `DigraphList/`：邻接表图结构（`DiGraphList.cs` 自注释"邻接链表"），顶点/边/算术拆为三分部文件
- 节点实体 `RedDotVertex`：携带 key、externalId、六态掩码（`RedDotType`）、运行时 info（状态/数值/脏标）等

支持菱形多父（A→B、A→C、B→D、C→D），普通树形红点系统无法表达的结构在语义上成立：D 同时聚合 B 与 C 的贡献。

## 边方向铁律
**边 =（父， 子）**。由此推出两条不变的传播方向：

- **脏传播**：`DataChange(叶子)` → 沿**入边**（inEdges）向上 BFS，把所有祖先标脏
- **状态聚合**：父节点沿**出边**（outEdges）向下 DFS，收集子节点贡献

从父节点报脏不会让子节点重算——`DataChange` 语义是"该节点的数据源变更了"（通常是叶子），这决定了 checker 只该挂在叶子上。

## 刷新算法：BFS 标脏 + DFS 聚合
```
DataChange(key[, id])
  → Batched 入队（Immediate 同帧） / 未就绪期缓冲 FIFO
  → 帧末 FlushPendingChanges（每帧至多 MaxDispatchPerFrame=64 项削峰）
  → 当前帧内 BFS 向上标脏（只标受影响链路）
  → 对脏链路 DFS 重算：子贡献 = 子状态 & 父掩码，零不采纳
      同数字态叠加 Value；跨态按覆盖优先级取高 → 归一为单态
  → 只通知当前帧（单帧全局模式下即全部）的订阅回调
  → 回调内 GetRedDotStatus 读时刷新取数（唯一取态语义）
```

关键性质：
- **零轮询**：没有定时器巡检；不报脏不重算，checker 读时才执行
- **掩码滤除告警**：checker 返回掩码外的状态位被滤除，编辑器模式下大声告警（防"节点静默不亮"难排查）
- **重入防护**：回调内禁止同步重入 `FlushPendingChanges`（库有防护）

## 六态状态与覆盖优先级
`RedDotStatus` 六态位掩码（位值不承载优先级）：

| 位 | 状态 | 含义 |
|---|---|---|
| 0 | `RedDotStatusRedDot` | 红点（无数字） |
| 1 | `RedDotStatusBlueDot` | 蓝点（无数字） |
| 2 | `RedDotStatusRedNumber` | 红点（有数字） |
| 3 | `RedDotStatusBlueNumber` | 蓝点（有数字） |
| 4 | `RedDotStatusTips` | "新"标签 |
| 5 | `RedDotStatusFull` | 满 |

覆盖优先级唯一权威 `RedDotStatusRules.PriorityOf`，优先级**秩**（大者胜）：

**满(6) > 红点(5) > 蓝点(4) > 红数字(3) > 蓝数字(2) > 新(1)**

- 注意：秩 ≠ 位值。`RedDotStatusFull` 位值是 `1 << 5 = 32`，秩是 6——**禁止直接比较位值判断谁覆盖谁**
- 优先级表 `PriorityByBit = { 5, 4, 3, 2, 1, 6 }`（下标 = 枚举位序）：调整优先级只改这一处，聚合算法零感知
- `NumberStatusMask`（红数字|蓝数字）：同数字态叠加 Value；跨态/跨类按优先级取高
- `AllStatusMask`：动态节点等"放行全部子贡献"场景的具名常量
- 运行时聚合结果（`info.RedDotStatus`）恒为**单态**；节点掩码（`v.RedDotType`）可为组合
- `RedDotStatusRules.Describe(mask)`：位值转可读名（"红点|红数字"），低频诊断/GM Dump 路径专用

## per-id 槽位模型
同一 key 可按 id 细分（列表/邮件格子场景）：每个 `(key, id)` 组合拥有独立运行时 info（状态+数值），id=0 为聚合槽位。

- `DataChange(key, id)` 报指定格子的脏；`GetRedDotStatus(key, id, ...)` 取指定格子
- **读时刷新/绑定即回放**：per-id 槽位只在被读或被绑定时刷新——长时间不打开的列表格子状态是陈旧的（这是有意设计，避免全列表常驻计算）
- 列表刷新后调用 `ReleaseCellIds(key, keep)` 收敛槽位（id=0 槽位库侧强制保留），防长列表只增不减
- cell 汇总聚合见 [红点使用指南](红点使用指南.md#cell-汇总列表场景) 的 `SummarizeCells`
