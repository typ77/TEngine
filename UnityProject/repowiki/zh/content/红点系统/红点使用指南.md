## 简介
面向业务的接入指南。业务只认两样东西：`RedDotKeys.XXX` 常量与 `RedDotGraphModule` 收口；**禁止直连 `RedDotManager`**（绕过配置缓冲与一致性自检）。原理视角见 [红点架构原理与图模型](红点架构原理与图模型.md)。

## 初始化与生命周期
- `GameApp.StartGameLogic` 已接线 `RedDotGraphModule.Instance.EnsureStarted()`：首启=激活（OnInit 自动完成 BeginConfigBuffering → AddFrame("Global") → RefreshMode=Batched → ILateUpdate 帧驱动 → 配置加载）
- 重登/切号若不重走 StartGameLogic，业务在登录流程自行再调 `EnsureStarted()`——第二次调用即 `Reinitialize()` 全量重建；**必须在 UI 重建之后调用**
- 配置未就绪期（JSON 还在异步加载）：`DataChange/AddUI/RemoveUI/SetNodeEnabled` 全量缓冲，就绪后 FIFO 重放，业务无须等待

## 基础接入四步
```csharp
// 1. 注册叶子 checker（聚合节点 externalId=-1 拒绝注册）
RedDotGraphModule.Instance.RegisterChecker(RedDotKeys.Mail_Unread, (out RedDotStatus s, out int n) =>
{
    int count = MailModule.UnreadCount;
    s = count > 0 ? RedDotStatus.RedDotStatusRedNumber : RedDotStatus.RedDotStatusNull;
    n = count;
});

// 2. 数据变更点报脏（挂在业务数据变更处，禁止挂 UI 回调；未就绪期自动缓冲）
RedDotGraphModule.Instance.DataChange(RedDotKeys.Mail_Unread);
RedDotGraphModule.Instance.DataChange(RedDotKeys.Mail_Unread, mailId);   // per-id

// 3. UI 绑定（见下节 RedDotWidget）

// 4. UI 卸载解绑
RedDotGraphModule.Instance.RemoveUI(RedDotKeys.Mail_Unread, OnRedDotChanged);
```

手工绑定（无 RedDotWidget 时）：`AddUI(key, cb[, id])` 注册即回放一次（绑定当帧取当前态），回调内用 `GetRedDotStatus` 读时刷新取态，与 `RemoveUI` 严格配对。

## RedDotWidget 组件
`UIWidget` 派生（`System/Common/RedDotWidget.cs`），六态唯一渲染出口（`RenderState` 先全熄再按单态点亮，数字 TMP 零分配 SetText，99+ 封顶 `CountCap`）。

**prefab 固定绑定**：节点挂 `RedDotKeyBinder`（Inspector 下拉选 RedDotKeys）+ `UIBindComponent` 八槽位：
`0=goFullDot 1=goDotTips 2=goReddot 3=goReddotNum 4=tmpReddot(TMP) 5=goBluedot 6=goBluedotNum 7=tmpBluedot(TMP)`

**运行时 API**：
| API | 说明 |
|---|---|
| `SetKey(string key, uint id = 0)` | 动态换绑（列表复用/Tab 数据驱动），创建时自动 AddUI 并回放 |
| `ClearKey()` | 解绑熄灭（空串换绑语义） |
| `SetLocalState(status, num)` | 本地直控：不入树、零订阅，纯表现场景 |
| `SetLocalVisible(bool)` | 本地显隐 |
| `Refresh()` | 手动刷新（回调外的强制重取） |
| `HideAllDots()` | 全熄 |
| `StatusModifier` | `Func<RedDotStatus, int, (RedDotStatus, int)>` 渲染前修饰钩子（本地二次加工） |

## 门控与即时冲刷
```csharp
// 未解锁系统：禁用吞报脏、不作 BFS 中继、读回 Null；启用补发父链重算
RedDotGraphModule.Instance.SetNodeEnabled(RedDotKeys.Arena, false);

// 显式即时冲刷（Batched 模式下不等帧末）：开窗瞬间等要"零延迟"的节点
RedDotGraphModule.Instance.FlushNow();
```

## cell 汇总（列表场景）
列表节点（如"邮件总红点"）由活跃格子态聚合而来，一行接入：

```csharp
// cellIdsProvider 每次刷新拉取当前活跃 cellId 集合;mask 通常传该节点配置的 redDotType
RedDotGraphModule.Instance.SummarizeCells(
    RedDotKeys.Mail.Key,
    () => _activeMailCellIds,
    RedDotStatus.RedDotStatusRedDot | RedDotStatus.RedDotStatusRedNumber);

// 列表刷新后收敛 per-id 槽位（id=0 槽位库侧强制保留），防长列表只增不减
RedDotGraphModule.Instance.ReleaseCellIds(RedDotKeys.Mail.Key, _activeMailCellIds);
```

语义：节点 id=0 态 = 对 cellIdsProvider 给出的 per-id 态聚合（状态按全序取高、数字态 Value 累加、mask 过滤）。有业务 WithId checker 的节点逐 cell 现算（保证列表未打开时总红点也正确）；`externalId=-1` 的系统段直写节点读 runtime info 缓存。
