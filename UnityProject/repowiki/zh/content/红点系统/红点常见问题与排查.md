## 运行期现象排查
| 现象 | 原因与处置 |
|---|---|
| **节点静默不亮** | 三种常见原因逐项排查：① checker 返回的状态位不在节点掩码内被滤除——编辑器模式下有 `WarnMaskFiltered` 类告警（日志含掩码与返回态的可读名），修掩码或修 checker；② 未报脏——`DataChange` 必须挂在数据变更点，报父节点不影响子节点；③ 门控未启用——`SetNodeEnabled(key, false)` 吞报脏且读回 Null |
| **checker 报脏了但不刷新** | Batched 模式帧末才派发（开窗瞬间需要零延迟用 `FlushNow()`）；确认回调内用 `GetRedDotStatus` 取态 |
| **UI 订阅收不到回调** | widget 未 `SetKey`/prefab 未挂 `RedDotKeyBinder`；或重登 `Reinitialize` 早于 UI 重建导致订阅丢失（EnsureStarted 必须在 UI 重建之后） |
| **`为聚合节点(externalId=-1)不可注册 checker`** | 改用其子叶子 key 注册；聚合节点的态来自子节点聚合 |
| **`构成了环`** | 配置图或运行时挂父成环，硬失败拒载；检查导出源图的引用节点接线与 `SetDynamicParent` 目标 |

## 版本与加载问题
| 现象 | 原因与处置 |
|---|---|
| `Could not found location [RedDotGraphConfig]` | 收集器未覆盖 `AssetRaw/Configs/Other` 或 JSON 未导出；模块 Warning 后图保持为空，业务操作照常（缓冲语义不炸） |
| `RedDotKeys 常量表与图配置不一致` | JSON 与热更 dll 版本错配（改图没重新导出/发版）；启动即 Warning 汇总，`ValidateKeysConsistency` 双向对账 |
| `红点配置加载失败 N 项` | 配置期只拦截**结构错误**（环/引用悬空）；叶子缺 checker 不在加载期拦截（checkVisitor 已关闭），降级为运行期 Warning——叶子补 `RegisterChecker` |
| 重登后红点全不亮/错乱 | 未调 `EnsureStarted` 或时序早于 UI 重建——重登/切号在 UI 重建后调用 `EnsureStarted()`（首启后的每次调用=全量重建） |

## 诊断工具
**GM/开发期诊断**（`RedDotManager.Ins()`，业务禁直连、诊断可用）：

```csharp
// 单节点快照：掩码/externalId/id=0 态/数值/脏标/per-id 条目数
Debug.Log(RedDotManager.Ins().DumpRedDotStatus(RedDotKeys.Mail.Key));

// "为什么亮了"：该 key 最近 8 次 DataChange 来源追踪
Debug.Log(RedDotManager.Ins().DumpChangeRecords(RedDotKeys.Mail.Key));
```

**模式确认**：
- 项目侧单帧全局模式：`AddFrame("Global")` 一次成型，永不切帧/删帧——被盖窗口（CanvasGroup alpha=0）照常收通知
- Batched 刷新：`MaxDispatchPerFrame=64` 削峰；Batched→Immediate 切换前须自行 `FlushNow`；回调内禁止同步重入 `FlushPendingChanges`（库有重入防护）
- 优先级排错：直接比较**位值**会得出相反结论（满的位值 32 < 新的位值 16，但满的优先级秩 6 最高）——一切比较走 `RedDotStatusRules.PriorityOf`
