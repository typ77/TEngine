## 简介
活动期次、邮件附件等运行时才确定数量/存亡的红点节点，不适合静态配在图里。动态节点在运行时以 `dyn:` 前缀命名空间挂进 DAG，随业务增删。

## 生命周期四件套
```csharp
// 新增一个活动期次红点（ownerKey 形如 act:123）
string ownerKey = Utility.Text.Format("act:{0}", activityId);
RedDotGraphModule.Instance.RegisterDynamicNode(ownerKey, out var dynKey);
RedDotGraphModule.Instance.SetDynamicParent(dynKey, RedDotKeys.Activity.Key);
RedDotGraphModule.Instance.BindDynamicChecker(dynKey, (out RedDotStatus s, out int n) => { ... });
RedDotGraphModule.Instance.DataChange(dynKey);

// 期次结束
RedDotGraphModule.Instance.RemoveDynamicNode(ownerKey);   // 摘边/摘 checker/父链补发
RedDotGraphModule.Instance.RemoveDynamicParent(dynKey);   // 只摘父边（父链逐 id 补发重算）
```

| API | 说明 |
|---|---|
| `RegisterDynamicNode(ownerKey, out dynKey)` | 注册动态节点，**同 ownerKey 幂等复用**同一 `dyn:` key |
| `SetDynamicParent(dynKey, parentKey)` | 挂父，走 DAG 环检测（构成环**硬失败**） |
| `BindDynamicChecker(dynKey, logic)` | 绑叶子 checker，重复调用**覆盖** |
| `RemoveDynamicNode(ownerKey)` | 删除动态节点（摘边/摘 checker/父链补发） |
| `RemoveDynamicParent(dynKey)` | 摘父边，父链补发重算 |

## key 命名与幂等
- 动态 key 由库生成（`dyn:` 前缀命名空间），业务只持有 ownerKey——不要自己拼 `dyn:` 字符串
- 同一 ownerKey 重复 `RegisterDynamicNode` 是幂等操作，返回同一 dynKey，不会产生重复节点
- `RemoveDynamicNode` 后重新注册得到新的生命周期

## 挂父重放（配置未就绪）
`SetDynamicParent` 在配置（红点图 JSON）尚未加载完成时调用是安全的：库登记到**挂父重放表**，配置加载完成（`SetConfigReady`）后自动补挂。父顶点不存在或成环仍是硬失败——业务无须记住"必须晚于配置加载"，但要知道报错时机可能在重放期。

## 销毁与全量重建
- `RemoveDynamicNode` 之外，动态节点不随场景切换销毁——它们挂在图上，生命周期由业务管理
- `Reinitialize()`（重登/切号全量重建）会 `RedDotManager.Reset()` 清空整张图（含动态节点与挂父重放表）——重建后业务需重新注册动态节点与 checker（checker 注册通常在模块初始化/登录流程，天然覆盖）
