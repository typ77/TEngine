## 简介
本项目的配置表系统为**自研 Excel 导表方案（Custom Config）**：策划在 Excel 中填表，编辑器工具一键导出为 C# 数据类代码与自定义二进制数据，运行时经 `ConfigSystem` 单例按需（懒加载）读取。2026-11 起本仓库已由 Luban 生成器方案整体切换为本方案（Luban 管线已移除）。

## 技术方案定位
- 生成格式：`cs`（C# 数据类 + 表类）+ `.bytes`（自定义二进制）
- 特性：懒加载（按行反序列化）、单表内共享缓存去重（≥8% 重复率自动启用）、组合索引、多语言列（`l`）、免反射建表注册
- 不依赖任何第三方导表工具；Excel 解析使用内嵌的 ExcelDataReader（Editor-only）
- 二进制反序列化复用 `GameProto/LubanLib/ByteBuf`（Luban 的运行时序列化库，仅作库使用，非 Luban 管线）

## 整体数据流
```
Configs/Tables/*.xlsx（源表，仓库内）
        │  Unity 菜单 Tools/配置表工具/生成全部数据(数据压缩)
        ▼
├── GameScripts/HotFix/GameProto/GameConfig/{Sheet}Item.cs   （生成代码，勿手改）
├── GameScripts/HotFix/GameProto/GameConfig/ConfigTableRegistry.cs（表工厂注册）
└── AssetRaw/Configs/Bytes/{Sheet}Config.bytes               （表数据，YooAsset tag "Configs"）

Configs/Language/Localization.xlsx（多语言工作簿，工具维护）
        ▼
AssetRaw/Configs/LanguageBytes/Language_{语言}.bytes

运行时：GameApp.StartGameLogic
  → ConfigSystem.Instance.InitLanguage() / InitConfig()
  → GetAssetInfos("Configs") 按 tag 并发加载 → ConfigTableRegistry 免反射建表
  → 业务 GetConfig<T>().GetItem(id) 按需反序列化
```

## 目录结构
| 目录 | 内容 |
|---|---|
| `Configs/Tables/` | 源 Excel（仓库内，路径由 `UpdateSetting.ConfigTablePath` 配置） |
| `Configs/Language/` | 多语言工作簿（`ConfigLanguagePath`） |
| `Assets/Editor/ExcelTool/` | 导表工具（Editor-only，含 BytesViewer 调试查看器） |
| `Assets/GameScripts/HotFix/GameProto/` | 运行时：ConfigSystem/TableBase/LanguageConfigItem/CustomConfig + `GameConfig/`（生成物） |
| `Assets/AssetRaw/Configs/Bytes/` | 表数据产物（`ConfigOutPutPath`） |
| `Assets/AssetRaw/Configs/LanguageBytes/` | 多语言产物 |

路径三项在 Project Setting → TEngine → Update Settings 中配置。

## 与其他模块的关系
- **YooAsset（IResourceModule）**：表 bytes 以 tag `Configs` 收集（AddressByFileName），`InitConfig` 按 tag 一次性并发加载；`TableBaseTemp` 解析完头部即 `UnloadAsset` 释放句柄
- **HybridCLR**：生成代码位于热更程序集 GameProto，表结构随热更包分发；数据 bytes 走资源热更
- **ILocalizationModule**：`InitLanguage` 读取当前语言并加载 `Language_{枚举名}.bytes`
- 详细加载原理见 [配置加载机制.md](配置加载机制.md)，表定义与使用见 [配置表定义规范.md](配置表定义规范.md)、[配置使用指南.md](配置使用指南.md)
