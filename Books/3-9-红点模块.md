# 3-9. 红点模块 - RedDotModule

## 🔄 模块概述

红点模块是基于 **DAG（有向无环图）** 的红点提示系统，移植自 [fermsi/RedDotGraph](https://github.com/fermsi/RedDotGraph) 并深度适配 TEngine 的 MVE 数据绑定体系。支持多层级红点聚合、多种红点状态优先级、运行时动态增删，以及可视化图编辑器配置。

### ✨ 核心优势

1. **🔗 DAG 架构，支持多父节点**
   - 支持菱形依赖（A→B, A→C, B→D, C→D），普通树形红点系统无法表达
   - 内置环检测，加边时自动拦截循环引用
   - 父节点状态自动聚合所有子节点

2. **🎨 多状态红点 + 优先级**
   - 普通 / 数量 / 新 / 满 四种状态（位掩码组合）
   - 自动取最高优先级显示（如 New 覆盖 Number）
   - 数量型节点支持子节点数值求和

3. **📊 MVE 数据绑定接入**
   - 每个红点节点一个 `BindableProperty<RedDotNodeState>`
   - UIWindow 在 `SetupBindings` 里 `Bind(node.State, ...)` 自动刷新
   - 状态变化经 `BatchScheduler` 帧末合并，避免中间态抖动

4. **⚡ 性能优化**
   - 标脏（dirty）+ BFS 向上传播，只重算受影响节点
   - `ILateUpdate` 帧末批量刷新
   - 全局时间戳去重，相同状态不重复回调

5. **🌱 动态叶子增删**
   - 列表项红点（邮件/任务/商品）运行时增删
   - 软删除方案（断边 + 对象池），不触发全图重映射
   - 聚合节点静态配置，叶子节点动态管理

## 📖 红点状态

```csharp
public enum RedDotStatus
{
    Null   = 0,   // 无红点
    Normal = 1,   // 普通红点（布尔型，仅显示圆点）
    Number = 2,   // 数量红点（显示具体数字）
    New    = 4,   // 新内容红点（"New" 标记）
    Full   = 8,   // 满额红点（如背包满）
}
```

- 位掩码设计，可组合（如 `Normal | Number | New = 7`）
- 节点配置 `redDotType` 声明允许的状态
- 运行时取最高优先级显示（Full > New > Number > Normal）

## 📖 快速上手

### 1. 配置红点树（JSON）

```json
{
  "vertexs": [
    { "key": "Root",       "redDotType": 2, "externalId": -1 },
    { "key": "Root.Mail",  "redDotType": 2, "externalId": 1 },
    { "key": "Root.Shop",  "redDotType": 1, "externalId": -1 }
  ],
  "edges": [
    { "key": "Root", "outKeys": ["Root.Mail", "Root.Shop"] }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `key` | 红点全局唯一标识 |
| `redDotType` | 允许的状态位掩码（Normal=1 \| Number=2 \| New=4 \| Full=8）|
| `externalId` | 叶子逻辑 ID（-1 表示聚合节点）|
| `edges.outKeys` | 子节点列表（边方向：父→子）|

### 2. 初始化

```csharp
var sys = RedDotSystem.Instance;

// 异步加载配置（遵循异步优先红线）
await sys.LoadJsonAssetAsync("Assets/AssetRaw/Config/reddot");
// 或 sys.LoadJsonText(jsonString);  // 直接加载文本

// 注册叶子逻辑（externalId 对应配置里的值）
sys.RegLogic(1, (out RedDotStatus s, out int n) =>
{
    int unread = MailModule.UnreadCount;
    s = unread > 0 ? RedDotStatus.Number : RedDotStatus.Null;
    n = unread;
});

// 配置加载后全量刷新
sys.RefreshAll();
```

### 3. UI 绑定（MVE 直接 Bind）

```csharp
protected override void SetupBindings()
{
    var node = RedDotSystem.Instance.GetNode("Root.Mail");
    if (node == null) return;
    Bind(node.State, state =>
    {
        m_go_Dot.SetActive(state.IsActive);
        if (state.Status == RedDotStatus.Number && state.Count > 0)
            m_text_Num.text = state.Count > 99 ? "99+" : state.Count.ToString();
    });
}
```

状态变化时 MVE 的 `BindableProperty` 自动触发回调，UIWindow 销毁时 `RemoveAllBindings` 自动解绑。

### 4. 触发刷新

```csharp
// 业务数据变化时（标脏叶子，BFS 向上传播到所有祖先）
RedDotSystem.Instance.MarkDirty("Root.Mail");
```

## 📖 核心 API

| 方法 | 说明 |
|------|------|
| `LoadJsonText(json)` / `LoadJsonAssetAsync(location)` | 加载红点树配置 |
| `RegLogic(id, delegate)` | 注册叶子判断逻辑（带 id / 不带 id 两版重载）|
| `GetNode(key)` | 获取节点门面（含 `BindableProperty<RedDotNodeState> State`）|
| `MarkDirty(key)` / `MarkDirty(key, id)` | 标记数据变更（脏传播 + 帧末刷新）|
| `RefreshAll()` | 全量刷新（配置加载后调用）|
| `AddLeaf/RemoveLeaf/ClearLeavesUnder` | 动态叶子增删（列表项红点）|
| `AddIdListener/RemoveIdListener` | 带 id 的列表项红点订阅 |

## 📖 动态叶子增删

列表项红点（邮件/任务/商品）运行时动态管理：

```csharp
// 打开邮件面板：为每封邮件添加叶子红点
foreach (var mail in mails)
{
    RedDotSystem.Instance.AddLeaf(
        key: $"Root.Mail.Item.{mail.Id}",
        parentKey: "Root.Mail",
        logicId: MAIL_ITEM_LOGIC_ID,
        allowed: RedDotStatus.Number);
}

// 关闭面板：批量清理
RedDotSystem.Instance.ClearLeavesUnder("Root.Mail");
```

**软删除方案**：不调用 `DiGraphList.Remove`（会触发 O(V+E) 全图 rank 重映射），而是断边（O(度数)）+ 从 key 映射移除 + 顶点归还对象池。

## 📖 关键设计点

### DataChange 语义（易错点）

`MarkDirty(key)` 标记的是"**数据源变更**的节点"。对于叶子，触发其 visitor 重算；BFS 沿入边向上传播到所有祖先。

> **陷阱**：从父节点调 `MarkDirty` **不会**让子节点重算。要让父重算，应标脏**叶子**（真正的数据源）。

### 带 id 的列表项红点

固定一个叶子节点 + 业务 id，适合"每封邮件一个红点"场景：

```csharp
RedDotSystem.Instance.AddIdListener("Root.Mail.Item", mailId, (status, value) => {
    // 刷新该项 UI
});
RedDotSystem.Instance.MarkDirty("Root.Mail.Item", mailId);
```

## 📖 GraphView 可视化编辑器

红点树结构可通过可视化图编辑器编辑：

1. **创建**：Project 窗口右键 `Create > Red Dot Graph`，生成 `.reddotgraph` 文件
2. **编辑**：双击打开，拖拽建节点、连线建父子关系（自动环检测）
3. **配置**：节点上选 key、逻辑ID、可存在状态（Normal/New/Number/Full）
4. **导出**：`导出红点配置` 生成 `.json`，运行时用 `LoadJsonAssetAsync` 加载

> 移植说明：原 fermsi 编辑器依赖 USS/UXML 资源文件，移植版改为**纯代码构建 UI**，去掉了资源依赖。
