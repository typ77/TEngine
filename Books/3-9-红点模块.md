# 3-9. 红点模块 - RedDotGraph

## 🔄 模块概述

红点模块是基于 **DAG（有向无环图）** 的红点提示系统，源自 [fermsi/RedDotGraph](https://github.com/fermsi/RedDotGraph)，经 Ljdmw 项目生产化演进后整体同步至 TEngine。支持六态红点、多父聚合、覆盖优先级、帧绑定回调、运行时动态节点、配置未就绪缓冲，以及可视化图编辑器与 key 常量表生成。

### ✨ 核心优势

1. **🔗 DAG 架构，支持多父节点**
   - 支持菱形依赖（A→B, A→C, B→D, C→D），普通树形红点系统无法表达
   - 内置环检测，加边时自动拦截循环引用（配置级错误硬报错）
   - 父节点状态自动聚合所有子节点，脏传播 BFS 全链收敛

2. **🎨 六态红点 + 覆盖优先级**
   - 红点 / 蓝点 / 红数字 / 蓝数字 / 新 / 满 六态（位掩码配置）
   - 覆盖优先级唯一权威 `RedDotStatusRules`：满 > 红点 > 蓝点 > 红数字 > 蓝数字 > 新（位值与优先级解耦，禁止直接比较位值）
   - 同数字态叠加 Value，跨态按优先级取高；归一后运行时结果恒为单态

3. **⚡ 刷新模式与性能**
   - `Immediate`（同帧派发）/ `Batched`（入队 + 帧末统一 BFS，每帧至多 MaxDispatchPerFrame 项削峰）
   - 标脏 + BFS 向上传播，只重算受影响节点；派发快照/队列/去重集全程复用零分配
   - 读时刷新（`GetRedDotStatus`）为唯一刷新语义，注册即回放保证绑定当帧取到当前态

4. **.frame 帧绑定回调模型**
   - `AddFrame/ChangeToFrame` 对应全屏面板切换，`AddUI` 只注册到当前帧
   - 项目侧采用单帧全局模式：`AddFrame("Global")` 一次，被盖窗口照常收通知
   - UI 订阅/取态全部经 `RedDotGraphModule` 收口，业务零直连

5. **🌱 动态节点 + 门控 + 缓冲**
   - 活动期次等列表项红点：`RegisterDynamicNode/SetDynamicParent/BindDynamicChecker/RemoveDynamicNode`（幂等，`dyn:` 前缀命名空间）
   - 未解锁系统：`SetNodeEnabled` 禁用吞 DataChange、不作 BFS 中继、读回 Null
   - 配置未就绪期：DataChange/AddUI/RemoveUI/SetNodeEnabled 全量缓冲，就绪后 FIFO 重放

## 📖 红点状态与优先级

```csharp
public enum RedDotStatus
{
    RedDotStatusNull       = 0,
    RedDotStatusRedDot     = 1 << 0,   // 红点(无数字)
    RedDotStatusBlueDot    = 1 << 1,   // 蓝点(无数字)
    RedDotStatusRedNumber  = 1 << 2,   // 红点(有数字)
    RedDotStatusBlueNumber = 1 << 3,   // 蓝点(有数字)
    RedDotStatusTips       = 1 << 4,   // 新标签位
    RedDotStatusFull       = 1 << 5,   // 满
}
```

- 节点配置 `redDotType` 为六态掩码（编辑器六态勾选框），声明允许显示/聚合的状态集
- 聚合规则：子贡献 = 子状态 & 父掩码，零不采纳；同数字态叠加 Value，跨态按覆盖优先级取高
- **覆盖优先级（高→低）：满 > 红点 > 蓝点 > 红数字 > 蓝数字 > 新**，唯一权威 `RedDotStatusRules.PriorityOf`
- checker 返回掩码外的状态位被滤除（编辑器模式下大声告警，防"节点静默不亮"难排查）；组合值归一取优先级最高位

## 📖 快速上手

### 1. 编辑器建图与导出

1. Project 窗口右键 `Create > 红点图`，生成 `.reddotgraph` 源资产，双击进入 GraphView 编辑器
2. 节点配置：key（Key 字典）、逻辑 ID（externalId 字典，-1=纯聚合）、六态勾选（掩码）
3. 分组子图：框选归组，组内是独立完整红点树、仅组根对外；主图放引用节点拼接；`dynamicMount` 组不连静态父，运行时 `SetDynamicParent` 挂载
4. 导出：窗口 Export 落盘运行时 JSON（紧凑序列化），标准地址 `Assets/AssetRaw/Configs/Other/RedDotGraphConfig.json`（文件名即 YooAsset 地址 `RedDotGraphConfig`），并同步再生成 key 常量表 `RedDotKeys.cs`
5. 双轴校验：结构轴（组/边拓扑 V 系）与 key 轴（未设置/悬空/重复 K 系）在面包屑与导出门禁拦截

### 2. 初始化（自动）

```csharp
// 正式业务零手动初始化:RedDotGraphModule.OnInit 自动完成——
//   BeginConfigBuffering(未就绪缓冲) → AddFrame("Global") → RefreshMode=Batched
//   → ILateUpdate 帧末驱动 FlushPendingChanges(SingletonSystem 随 Retain/Release 自动注册/注销,帧号判重防御)
//   → YooAsset 加载 RedDotGraphConfig → AddJsonStr → 常量表一致性自检 → SetConfigReady 重放
// 重登/切号在启动链调用:
RedDotGraphModule.Instance.EnsureStarted();   // 首启=激活;重登走 Reinitialize 全量重建
```

### 3. 注册 checker 与报脏（业务收口）

```csharp
// P0-5 收口:key 常量携带 externalId,业务零魔法数;聚合节点(externalId=-1)拒绝注册
RedDotGraphModule.Instance.RegisterChecker(RedDotKeys.Mail_Unread, (out RedDotStatus s, out int n) =>
{
    int count = MailModule.UnreadCount;
    s = count > 0 ? RedDotStatus.RedDotStatusRedNumber : RedDotStatus.RedDotStatusNull;
    n = count;
});

// 报脏:数据变更点的业务逻辑里调用(禁止挂在 UI 回调里);未就绪期自动缓冲
RedDotGraphModule.Instance.DataChange(RedDotKeys.Mail_Unread);
// per-id 场景:同一 key 按 id 细分(cell 粒度),示例以未读邮件 key 的 id 维度演示
RedDotGraphModule.Instance.DataChange(RedDotKeys.Mail_Unread, mailId);
```

### 4. UI 绑定（RedDotWidget 组件）

```csharp
// prefab:widget 节点挂 RedDotKeyBinder（Inspector 下拉选 RedDotKeys）+ UIBindComponent 八槽位
//   0=goFullDot 1=goDotTips 2=goReddot 3=goReddotNum 4=tmpReddot(TMP) 5=goBluedot 6=goBluedotNum 7=tmpBluedot(TMP)
// 固定绑定:binder 序列化 key,widget 创建时自动 AddUI
// 动态绑定(列表复用/Tab 数据驱动):SetKey 运行时换绑,空串=解绑熄灭
m_widget.SetKey(RedDotKeys.Mail_Unread.Key, cellId);
m_widget.ClearKey();
// 本地直控(不入树,零订阅,纯表现场景):
m_widget.SetLocalState(RedDotStatus.RedDotStatusRedDot);
```

回调模型：`AddUI 注册即回放一次`（绑定当帧即取当前态），状态变化时回调内 `GetRedDotStatus` 读时刷新取态，`RenderState` 先全熄再按单态点亮（六态唯一渲染出口，数字 TMP 零分配 SetText，99+ 封顶）。

手工绑定（无 RedDotWidget 时）：

```csharp
RedDotGraphModule.Instance.AddUI(RedDotKeys.Mail_Unread, OnRedDotChanged);
RedDotGraphModule.Instance.GetRedDotStatus(RedDotKeys.Mail_Unread, 0, out var status, out var num);
RedDotGraphModule.Instance.RemoveUI(RedDotKeys.Mail_Unread, OnRedDotChanged);   // 与 AddUI 配对
```

## 📖 核心 API（RedDotGraphModule 收口）

| 方法 | 说明 |
|------|------|
| `RegisterChecker(key, logic)` / `(key, logicWithId)` | 注册叶子 checker（P0-5 收口，聚合节点拒绝） |
| `DataChange(key[, id])` | 报脏（Batched 入队 / Immediate 同帧派发；未就绪期缓冲） |
| `AddUI(key, cb[, id])` / `RemoveUI` | UI 订阅/解绑（注册即回放；未就绪期缓冲/对冲） |
| `GetRedDotStatus(key, id, out status, out num)` | 读时刷新取态（回调内取态唯一入口） |
| `SetNodeEnabled(key, enabled)` | 节点门控（禁用吞报脏/读回 Null，启用补发父链） |
| `RegisterDynamicNode(ownerKey, out dynKey)` | 动态节点注册（幂等，`dyn:` 前缀） |
| `SetDynamicParent(dynKey, parentKey)` | 动态节点挂父（未就绪登记重放，环检测硬失败） |
| `BindDynamicChecker(dynKey, logic)` | 动态叶子绑 checker（重复调用覆盖） |
| `RemoveDynamicNode(ownerKey)` / `RemoveDynamicParent` | 删除动态节点/摘父边（父链逐 id 补发重算） |
| `SummarizeCells(key, idsProvider, mask)` | cell 汇总标准 checker（列表 per-id 聚合一行接入） |
| `ReleaseCellIds(key, keep)` | 按 keep 集收敛 per-id 槽位（长列表防只增不减） |
| `FlushNow()` | 显式即时冲刷（开窗/切帧等节点） |
| `EnsureStarted()` / `Reinitialize()` | 启动链入口 / 重登全量重建 |
| `ValidateKeysConsistency()` | 常量表 vs 图双向对账（版本错配启动即报） |

## 📖 动态节点（列表项红点）

活动期次/邮件附件等运行时增删的红点：

```csharp
// 新增一个活动期次红点(ownerKey 形如 act:123)
string ownerKey = Utility.Text.Format("act:{0}", activityId);
RedDotGraphModule.Instance.RegisterDynamicNode(ownerKey, out var dynKey);
RedDotGraphModule.Instance.SetDynamicParent(dynKey, RedDotKeys.Activity);
RedDotGraphModule.Instance.BindDynamicChecker(dynKey, (out RedDotStatus s, out int n) => { ... });
RedDotGraphModule.Instance.DataChange(dynKey);

// 期次结束
RedDotGraphModule.Instance.RemoveDynamicNode(ownerKey);   // 摘边/摘 checker/父链补发
```

要点：同 ownerKey 幂等复用同一 `dyn:` key；挂父走 DAG 环检测（构成环硬失败）；父顶点未就绪（配置未加载）自动登记重放表，配置加载完成后补挂——业务无须记住"必须晚于配置加载"。

## 📖 关键设计点

### DataChange 语义（易错点）

`DataChange(key)` 标记的是"**数据源变更**的节点"（通常是叶子）。脏传播沿入边向上到所有祖先；从父节点报脏不会让子节点重算。

### 禁止直连 RedDotManager

业务只认 `RedDotKeys.XXX` 常量与 `RedDotGraphModule` 收口。直连 Manager 会绕过 P0-3 配置缓冲与一致性自检；`RedDotKeys` 常量表为生成物（`RedDotKeysGenerator` 随导出产出），禁止手改。

### Batched 刷新契约

项目侧默认 Batched（对齐旧 500ms 合并的抗风暴价值，延迟降为 1 帧）。Batched→Immediate 切换前须自行 Flush；回调内禁止同步重入 `FlushPendingChanges`（有重入防护）。

## 📖 GraphView 可视化编辑器

1. **创建**：Project 窗口右键 `Create > 红点图`，生成 `.reddotgraph` 文件
2. **编辑**：双击打开，拖拽建节点、连线建父子关系（自动环检测）；Key/逻辑ID 双字典 + 搜索窗口
3. **分组子图**：框选归组、组树嵌套、dynamicMount 动态挂载组；双轴校验（结构轴 V 系 + key 轴 K 系）实时暴露配置问题
4. **导出**：窗口 Export 生成运行时 JSON（分组展平：引用节点替换为组根，边按目标 redDotType 降序）+ 同步再生成 `RedDotKeys.cs`（`<auto-generated>` 头、成员名非法字符转 `_`、按成员名 Ordinal 排序、中文 desc 注释、聚合节点标注不可注册）
