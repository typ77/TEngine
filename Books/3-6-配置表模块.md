# 3-6. 配置表模块 - ConfigSystem

> **注**：本仓库（2026-11 起）配置表系统已由 TEngine 上游的 **Luban 方案**切换为**自研 Excel 配置表系统（Custom Config）**。本章前两节介绍本仓库现行实现及其与 Luban 的横向对比；第三节起为上游 Luban 方案的介绍，仅作背景阅读与选型参考。

## ⭐ 本仓库实现：自研 Excel 配置表系统（Custom Config）

自研 Excel → C# 代码 + 自定义二进制的配置管线（移植自商业化小游戏项目 LjdmwMiniClient），不依赖任何第三方导表工具。

### 数据流

```
Configs/Tables/*.xlsx（源表，仓库内）
        │  Unity 菜单 Tools/配置表工具/生成全部数据(数据压缩)
        ▼
├── GameScripts/HotFix/GameProto/GameConfig/{Sheet}Item.cs   （生成代码，勿手改）
├── GameScripts/HotFix/GameProto/GameConfig/ConfigTableRegistry.cs（表工厂注册）
└── AssetRaw/Configs/Bytes/{Sheet}Config.bytes               （表数据，YooAsset tag "Configs"）

Configs/Language/Localization.xlsx（多语言工作簿，工具维护）
        ▼
AssetRaw/Configs/LanguageBytes/Language_{语言}.bytes
```

### 核心特性

1. **表结构表内自描述**：A 列标签行（`##lb-row##` / `##lb-labels##` / `##lb-target##` / `##lb-keys##` / `##lb-names##`）声明主键、类型、字段名与输出平台，无独立定义文件
2. **行级懒加载**：启动只解析头部（key→offset 索引），`GetItem(id)` 按行反序列化并入缓存，miss 负缓存；全表缓存满自动释放句柄；每次重载 `ConfigSystem.ConfigLoadVersion` 自增供派生缓存失效
3. **共享缓存去重**：字段重复率 ≥8% 自动启用，唯一值入静态字典、行内只存 int 索引（string/list/dict/复合对象）
4. **免反射建表**：`ConfigTableRegistry` 合并生成工厂，启动零 `Assembly.GetType`
5. **多语言闭环**：`l` 标记列自动收集进 Language 工作簿并分配 id，bytes 内只存 int，运行时 `GetLanguageString(id)` 还原
6. **组合索引**：`~` 前缀列生成 `GetIdByCompoundKey_*` / `TryGetIdByCompoundKey_*` / `EnumerateCompoundIndex_*` 三件套查询方法
7. **编辑器配套**：数据生成窗口（单文件/单 sheet 导出）、Bytes 调试查看器（bytes→JSON/CSV/diff/回导 xlsx）、共享缓存压缩率报告

现行规范唯一权威入口：`UnityProject/.claude/skills/custom-config/`（含表定义规范、访问治理、示例表）。

## ⚖️ Custom 与 Luban 横向对比

### 总览对比表

| 维度 | Luban（上游原方案） | Custom Config（本仓库现行） |
|---|---|---|
| **工具链** | 外部 dotnet 工具（需 clone luban-next 源码编译 Luban.dll） | Unity Editor 内置插件（纯 C#，ExcelDataReader 内嵌），零外部依赖 |
| **表结构定义** | `luban.conf` + `__tables__.xlsx` 注册 + `__beans__/__enums__.xlsx` + Defines XML | Excel 表头标签行自描述，一张表搞定 |
| **类型系统** | 强：bean 多态继承、枚举、外部类型映射（UnityEngine.Vector）、可空、容器齐全 | 够用：基本类型（bool/byte/short/int/long/uint/ulong/float/double/str）+ vec2/vec3/vec4/quat + 数组/list/dict/元组嵌套 + 四种固定格式复合对象（color/datetime/vec2int/vec3int/decimal/obj/enum 解析可用但二进制写入端未实现，暂不可导出） |
| **数据校验** | 内置丰富校验器（ref 引用、path 资源、range 范围等） | Schema/Data 两级校验（类型、主键、标识符、复合对象格式） |
| **生成物** | `Tables.cs` 聚合类 + 每表 `TbXxx`/`Xxx` | 一表一文件 `{Sheet}Item.cs`（数据类+表类）+ `ConfigTableRegistry.cs` |
| **数据格式** | Luban bin（统一二进制） | 自定义 bytes：可选共享缓存段 + 行数 + key/offset 索引 + 数据区 |
| **加载策略** | 表级懒加载（Tables 属性首次访问整表构造） | **行级懒加载** + miss 负缓存 + 全表缓存满自动释放句柄 |
| **内存优化** | 无自动去重 | **共享缓存自动去重**（≥8% 重复率字段） |
| **启动成本** | 模板内 `Assembly.GetType` + Activator 反射 | 免反射工厂注册表 |
| **多语言** | 无内置，需自行集成 | **内置闭环**（l 列 → 多语言工作簿 → Language bytes → GetLanguageString） |
| **双端支持** | 原生 multi-target（server/client/all 分组，可输出服务端工程） | 字段级标记（lb-target c/s/cs），无服务端工程输出 |
| **编辑器集成** | 菜单调 bat 脚本 | 菜单 + 数据生成窗口 + Bytes 调试查看器 + 压缩率报告 |
| **生态与文档** | 官方文档/社区成熟（datable.cn） | 无外部文档，依赖仓库内 skill/wiki/本章 |
| **主键** | 支持多主键 | 单主键（`##lb-labels##` 的 `#` 列；类型校验允许 int/uint/long/ulong/short/ushort/str/string，惯例用 int/string） |

### 差异分析

**1. 工具链自主性（Custom 的核心动机）**
Luban 功能强大，但引入外部工具链依赖：工具本体不进仓库（需自行编译）、版本升级要同步 luban-next、CI 环境要装 dotnet。Custom 是纯 C# 源码内嵌 Editor 目录，随仓库走、可随意改，对微信小游戏这类"轻配置、重加载性能"的项目，维护成本显著更低。

**2. 类型表达能力（Luban 的核心优势）**
Luban 的 bean 多态 + 枚举 + 外部类型映射 + ref 校验构成完整类型系统，适合技能/行为树这类强结构化配置。Custom 刻意保持简单：复杂结构靠 list/dict/元组嵌套与四种固定格式对象（RewardObject 等）表达；代价是无多态、单主键，复杂表的可表达性弱于 Luban。

**3. 加载与内存（Custom 面向小游戏优化）**
- Luban：表级懒加载——首次访问某表时整表反序列化，大表（MB 级）首访有明显卡顿与内存峰值；
- Custom：行级懒加载——启动只建 key→offset 索引，单行查询 O(1) 零 GC（命中缓存），配合共享缓存去重，大表的内存占用与首访卡顿都显著更优。两者运行时入口 API 名字相同（`ConfigSystem`），但内部策略不同。

**4. 启动成本**
Custom 免反射注册表消除 `Assembly.GetType + Activator.CreateInstance`（400+ 张表时反射成本毫秒级且产生 GC），这是源项目实测优化（GetConfig 高频路径 2.47ms → 0）。

**5. 多语言一体化**
Custom 把多语言当作配置表的一等公民（列级 `l` 标记自动收集、id 化、多语言 bytes 与运行时还原内置）；Luban 需要额外建设。做多语言项目的成本差异很大。

**6. 双端与生态**
若项目需要服务端消费同一套配置（输出服务端代码工程），Luban 的 multi-target 是硬优势；Custom 只做字段级 c/s 过滤，服务端需要另建读取端。生态上 Luban 有官方文档与社区，Custom 的知识都在仓库内（skill/wiki），对外部新人有一土一洋的差别。

### 选型建议

- **强类型复杂配置 / 需要服务端同源输出** → Luban
- **零外部依赖 / 行级懒加载 / 内存敏感（小游戏）/ 多语言一体化 / 团队自主可控** → Custom（本仓库选择）

## 📊 模块概述（上游 Luban 方案，本仓库未采用，仅作背景与选型参考）

TEngine 上游配置表模块集成了 **[Luban](https://github.com/focus-creative-games/luban)**，提供了完整的配置表开发工作流。

### ✨ 核心优势

1. **🚀 多种加载方式**
   - **懒加载**：按需加载配置，节省内存
   - **异步加载**：基于 UniTask 的异步加载，不阻塞主线程
   - **同步加载**：快速同步加载配置
   - **服务器加载**：支持 Task 异步加载（服务器端）

2. **📦 强大的数据支持**
   - 支持 Excel、JSON、XML、YAML 等多种数据格式
   - 支持复杂嵌套结构
   - 支持 OOP 类型继承

3. **✅ 完善的数据校验**
   - ref 引用检查
   - path 资源路径检查
   - range 范围检查
   - 类型安全检查

4. **🌍 本地化支持**
   - 静态文本值本地化
   - 动态文本值本地化
   - 时间本地化
   - main-patch 多地区版本

## 📁 目录结构

在 TEngine 中，Luban 配置表目录位于：

```
Configs/GameConfig/
├── CustomTemplate/      # 自定义模板
├── Datas/              # 配置表数据（Excel）
├── Defines/            # 配置表定义
└── gen_code_*.bat      # 代码生成脚本
```

生成产物路径：

- **二进制数据文件**：`Assets/AssetRaw/Configs/bytes/`（由资源模块加载）
- **C# 代码**：`GameScripts/HotFix/GameProto/GameConfig/`（热更程序集，Luban 生成）

## 🛠️ 安装与配置

### 1. 安装 Luban

在 TEngine 根目录同级克隆最新的 luban-next 仓库：

![image](src/3-6-2.png)

### 2. 构建 Luban

在 `Tools` 目录执行 `build-luban.bat`（Windows）或 `build-luban.sh`（Mac/Linux）：

![image](src/3-6-3.png)

### 3. 生成配置表代码

在 `Configs/GameConfig` 目录下执行对应的生成脚本：

- `gen_code_bin_to_project.bat` - 生成客户端代码（同步加载）
- `gen_code_bin_to_project_lazyload.bat` - 生成客户端代码（懒加载）
- `gen_code_bin_to_server.bat` - 生成服务器代码

> **提示**：TEngine 内置默认使用懒加载配置，也支持基于 UniTask 的异步加载、同步加载，包括服务器的 Task 异步加载。

## 📖 使用指南（上游 Luban 方案 API，本仓库不适用）

> 以下 `ConfigSystem.Instance.Tables.TbItem` 为 Luban 生成物 API。本仓库现行 API 是 `ConfigSystem.Instance.GetConfig<T>().GetItem(id)`，见本章开头"本仓库实现"一节。

### 基础使用

```csharp
/// <summary>
/// 道具配置表管理器。
/// </summary>
public class ItemConfigMgr : Singleton<ItemConfigMgr>
{
    /// <summary>
    /// 道具 Table。
    /// </summary>
    private TbItem TbItem => ConfigSystem.Instance.Tables.TbItem;

    /// <summary>
    /// 获取道具配置表。
    /// </summary>
    /// <param name="itemId">道具Id。</param>
    /// <returns>道具配置表。</returns>
    public ItemConfig GetItemConfig(int itemId)
    {
        if (TbItem.DataMap.TryGetValue(itemId, out var config))
        {
            return config;
        }
        return null;
    }
    
    /// <summary>
    /// 获取所有道具配置。
    /// </summary>
    /// <returns>所有道具配置列表。</returns>
    public List<ItemConfig> GetAllItemConfigs()
    {
        return TbItem.DataList;
    }
}
```

### 懒加载模式（推荐）

```csharp
// 懒加载：首次访问 Tables 属性时自动加载
var itemConfig = ConfigSystem.Instance.Tables.TbItem.Get(itemId);
```

### 同步加载模式

```csharp
// 同步加载所有配置表
ConfigSystem.Instance.Load();
var itemConfig = ConfigSystem.Instance.Tables.TbItem.Get(itemId);
```

## 🔧 Luban 核心特性

### 1. 强大的数据解析和转换能力

支持多种数据格式输入和输出：

**输入格式**：
- Excel (CSV, XLS, XLSX)
- JSON
- BSON
- XML
- YAML
- Lua
- Unity ScriptableObject

**输出格式**：
- Binary
- JSON
- BSON
- XML
- Lua
- YAML
- Erlang
- Custom Format

### 2. 增强的 Excel 格式

可以简洁地配置出：
- 简单列表
- 子结构
- 结构列表
- 任意复杂的深层次嵌套结构

### 3. 完备的类型系统

- 支持 OOP 类型继承
- 灵活优雅表达行为树、技能、剧情、副本等复杂 GamePlay 数据

### 6. 强大灵活的自定义能力

- 支持自定义代码模板
- 支持自定义数据模板
- 通用型生成和缓存工具
- 也可以用于生成协议、数据库之类的代码

## 💡 最佳实践（上游 Luban 方案 API，本仓库不适用）

> 同上，以下示例为 Luban API 写法，仅作背景阅读。

### 1. 使用懒加载模式

对于大型项目，推荐使用懒加载模式，按需加载配置：

```csharp
// ✅ 推荐：懒加载，按需加载
var config = ConfigSystem.Instance.Tables.TbItem.Get(itemId);
```

### 2. 创建配置表管理器

为每个配置表创建管理器，统一管理配置访问：

```csharp
public class ItemConfigMgr : Singleton<ItemConfigMgr>
{
    private TbItem TbItem => ConfigSystem.Instance.Tables.TbItem;
    
    public ItemConfig GetItemConfig(int itemId)
    {
        return TbItem.Get(itemId);
    }
}
```

### 3. 使用配置表验证

在配置表定义中使用验证特性：

```csharp
// 在 Luban 配置表中使用验证
item_id: int, ref: TbItem;  // 引用检查
item_count: int, range: [1, 999];  // 范围检查
item_path: string, path: "Assets/";  // 路径检查
```
