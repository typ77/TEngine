## 1. Timer 模块重写

> 🔄 **重写** · 影响文件：`Assets/TEngine/Runtime/Module/TimerModule/`

### 问题

原定时器模块基于**线性遍历**查找到期定时器，定时器数量增长后效率低下，多定时器场景下形成性能瓶颈。频繁创建销毁 Timer 对象产生 GC 压力，且缺少运行时调试手段。

### 方案

| 改动 | 说明 |
|------|------|
| 最小堆调度 | 使用 `IndexedMinHeap` 替代线性遍历，定时器到期查找从 O(n) 降至 O(log n) |
| 对象池化 | `TimerNode` 对象池复用，消除频繁 new 产生的 GC |
| 诊断窗口 | Editor 窗口实时展示 Active / Zombie / Pool 定时器状态 |

### 状态

✅ 已完成 · 23 个 EditMode 测试覆盖

## 2. UI 数据绑定系统

> 🆕 **新增** · 影响目录：`Assets/GameScripts/HotFix/GameLogic/Module/DataBinding/`、`UI/LoginUI/`

### 问题

原 UI 刷新完全依赖手动调用 `OnRefresh()`，存在以下痛点：

- **数据变了 UI 不知道** — 玩家升级了，主界面等级没刷新
- **同一数据多处展示** — 金币在主界面、商店、背包都有显示，改一处要改三处
- **OnRefresh 粒度太粗** — 道具数量变了要刷新整个列表
- **手动调 OnRefresh 容易遗漏** — 业务逻辑改了数据忘记通知 UI

### 方案

引入轻量级响应式数据绑定模块，与现有 `OnRefresh` / `GameEvent` 共存：

| 组件 | 说明 |
|------|------|
| `BindableProperty<T>` | 响应式属性包装器，赋值自动通知订阅者 |
| `ObservableList<T>` | 响应式集合，增删改事件驱动 |
| `BatchScheduler` | 帧级批次合并，同帧多次赋值合并为一次回调 |
| `DataContext` | 多源聚合 + 格式转换，View 不直接依赖 Model |
| 便捷方法 | `BindText` / `BindInteractable` / `BindToggle` / `BindSlider` / `BindSprite` |
| MVE 四层架构 | Model → Service → DataContext → View，按业务单位组织文件 |

```
数据流：Model 赋值 → BatchScheduler 帧末合并 → DataContext 转换 → View 自动刷新
```

### 状态

✅ 已完成 · 102 个测试覆盖 · [详细文档](../UnityProject/repowiki/zh/content/UI系统/UI数据绑定.md)

## 5. FancyScrollView 列表系统改造

> 🔄 **重写** · 影响目录：`Assets/GameScripts/HotFix/GameLogic/Module/UIModule/FancyScrollView/`、`UI/FancyScrollViewExamples/`、`Assets/Editor/FancyScrollView/`

### 问题

原 TEngine 无内置高性能动画列表组件。引入开源 [FancyScrollView](https://github.com/setchi/FancyScrollView) 后，其 Cell 基于 MonoBehaviour，无法融入 TEngine 的 UIWidget / MVE 体系，也不能被 ScriptGenerator 自动生成绑定——列表开发仍需大量手写样板代码，Cell 的生命周期、数据绑定、异步内容加载都要各自处理。

### 方案

| 改动 | 说明 |
|------|------|
| Adapters 适配层 | 新增基于 UIWidget 的 `FancyCellWidget`（支持 MVE 绑定、异步内容加载、进出场动画）；纯 C# 控制器 `FancyScrollerController` / `FancyScrollRectController` / `FancyGridViewController`（组合模式，规避泛型 MonoBehaviour 无法 AddComponent 的限制） |
| ScriptGenerator 集成 | `m_scroller_` 节点前缀配对自动生成 Controller 字段、CellFactory、OnDestroy Dispose；Cell 经 UIBindComponent 无基类生成绑定 |
| Example 全量 MVE 化 | Example01 ~ Example09 按四层架构（Model / Service / DataContext / View）重组，Cell / Widget prefab 规范化，选中态统一为 `FancySelectionContext` |
| Editor 工具 | `DropdownTemplateFixer`（批量修复 Dropdown 缺失 Template 子节点）、`FancyScrollerMenu` / `FancyScrollRectMenu`（标准节点右键创建菜单） |
| 质量加固 | carousel 渲染层级修复（sibling order）、性能优化（Vector 运算顺序 / Dictionary 访问）、GridView 重影与 scrollbar 修复 |

### 状态

✅ 已完成 · 56 个提交 · 22 个 EditMode 用例（7 个测试文件）

## 6. 红点系统

> 🆕 **新增** · 影响目录：`Assets/GameScripts/HotFix/GameLogic/Module/RedDotModule/`、`UI/RedDotDemo/`

### 问题

原 TEngine 无内置红点提示系统。游戏开发中红点需求普遍（未读邮件、新任务、可领取奖励），手写实现常见痛点：

- **父子聚合靠人肉维护** — 邮件入口的红点要手动检查系统邮件+玩家邮件两个子项，易遗漏
- **多状态红点难表达** — "新功能"红点和"未读数量"红点优先级关系混乱
- **列表项红点性能差** — 每封邮件一个红点，增删时全量刷新
- **无统一配置** — 红点关系散落代码各处，策划无法参与配置

### 方案

移植 [fermsi/RedDotGraph](https://github.com/fermsi/RedDotGraph) 的 DAG 红点核心，深度适配 TEngine 的 MVE 数据绑定体系：

| 改动 | 说明 |
|------|------|
| DAG 架构 | 有向无环图支持多父节点（菱形依赖），内置环检测，普通树形红点无法表达的关系可建模 |
| 多状态优先级 | Normal/Number/New/Full 四种状态（位掩码），自动取最高优先级显示 |
| MVE 接入 | 每个红点节点一个 `BindableProperty<RedDotNodeState>`，UIWindow `Bind()` 自动刷新，与 LoginUI 范式一致 |
| 标脏 + 帧末批处理 | BFS 向上传播脏标记，`ILateUpdate` 帧末统一刷新，全局时间戳去重 |
| 动态叶子增删 | 列表项红点运行时 `AddLeaf`/`RemoveLeaf`，软删除方案（断边+对象池）不触发全图重映射 |
| 可视化编辑器 | GraphView 图编辑器（拖拽建图/环检测/Key管理/枚举生成），导出 JSON 配置，纯代码构建 UI 无 USS/UXML 依赖 |
| 配置驱动 | JSON 配置红点树结构（`vertexs` + `edges`），运行时 `LoadJsonAssetAsync` 异步加载 |

```
数据流：叶子数据变化 → MarkDirty → BFS 标脏传播 → 帧末 DFS 聚合
  → ApplyRefreshedState 写入 BindableProperty → BatchScheduler 合并 → UI 自动刷新
```

### 代码审查与规范化

移植后做了完整的代码规范性审查（对照 TEngine 命名规范/MVE 模式/异步红线），修复：
- `async void` → `async UniTask`（异步红线）
- 删除同步 `LoadJsonAsset`（违反异步优先）
- 删除孤立 `RedDotWidget` 组件 + 死代码 `RedDotDemoBoot`
- `MarkDirty(key,id)` 补全全局联动逻辑
- `AddIdListener` 重复订阅加 Warning
- 逻辑 ID 魔法数字抽共享常量类
- DemoBuilder 节点命名加 `m_` 前缀（符合 ScriptGenerator 规范）
